The product

The product

Tell KryptoLens what matters. Give it a job. It keeps watch for you.

The problem

The problem

Someone who can name a crypto-market job in language wants a teammate that stays on it, not a dashboard they have to configure.

The approach

The approach

A Lens is a persistent crypto agent with a compiled job, workflow, routines, tool permissions, conversation, and results; AgentRuntime plans then LensRuntime/workflow hits live CMC and writes verified results back.

Persistent Lens / Agent

Persistent Lens / Agent

A Lens is a user-owned persistent crypto agent with name, purpose, natural-language request, status (draft/active/paused), versions, routines, conversation, and results.

Natural-language job compile and conversation

Natural-language job compile and conversation

Authenticated users describe a job; ConversationService handles intent/actions on the lens detail page, including run, preview, and draft diffs.

Chief Agent planning

Chief Agent planning

Chief Agent emits a schema-validated AgentPlan (monitor/investigate/research) with allowed steps and tools; plans do not call CMC.

Closed CMC workflow execution

Closed CMC workflow execution

WorkflowDefinition allows a fixed step set (universe/listings, quotes, global metrics, fear & greed, calculate, sort, filter, aggregate, present) and optional asset_condition triggers.

AgentRuntime loop with verification

AgentRuntime loop with verification

AgentRuntime wraps LensRuntime in PLAN → ACT → OBSERVE → VERIFY → REPAIR? → COMPLETE, sharing Check now and scheduled paths.

Unattended Beat / routines

Unattended Beat / routines

Celery task run_active_lenses enqueues due routines via RoutineService; run_lens executes the same AgentRuntime path as manual checks.
